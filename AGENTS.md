# Agents

## Working rules

- Edit code and JSON, then run the Launcher commands below and tell the user what to test. Don't byte-scan map binaries or compare timestamps to verify; the user tests in-game.
- Follow `.github/copilot-instructions.md`
- A compile check is fine: `dotnet build Source/Source.csproj`.
- Launcher commands (no menu), run from `Launcher/bin/Debug/net8.0` after `dotnet build Launcher/Launcher.csproj`: `dotnet Launcher.dll import-objects` (menu 6 > 7), `compile` (option 2), `deploy` (option 7, the map the user hosts from). `export-objects` (menu 6 > 6) overwrites the JSON with the map's current data, so only use it to pull in changes made in the World Editor, and never while JSON edits are pending import.
- Multi-line PowerShell pasted into the terminal gets echoed, not run. Write a `.ps1` to `%TEMP%` and run it with `powershell -NoProfile -ExecutionPolicy Bypass -File`.

## Editing map object data

Launcher > 6 (Wc3 Map Tools): 6 exports, 7 imports. Edit the JSON in `Launcher/W3MapTool/ObjectData/` between them. After editing, only import (7); exporting first overwrites the edits. The map only changes once 7 has run, so if edits seem ignored the user probably hasn't re-imported.

- Skin files (except destructables) and `war3map.wts` are never touched, so new objects need literal `unam`, `utip` and `uico` strings. Items also need `iico` for the inventory icon.
- Update `Source/AutoGenerated/Constants.cs` for new ids, or run Launcher > 1.
- Only JSON changes need the import. Changes to C# or `.blp` files just need Launcher > 7.
- Custom icons go in `source.w3x/war3mapImported/` and are referenced as `war3mapImported\\Name.blp` (C# and JSON). Each also needs a greyed `DISBTNName.blp` in `source.w3x/ReplaceableTextures/CommandButtonsDisabled/`, or the vendor's disabled view shows a green square (the `-shop` frame and inventory load the BTN path directly, so they look fine without it). Don't re-encode a BTN `.blp` by hand: the original works as is.
- To generate the `DISBTN` from a BTN: `powershell -NoProfile -ExecutionPolicy Bypass -File Scripts\New-DisBtn.ps1 -Name ChainedRing [-Preview]` (BTN name without the `BTN` prefix). It reads `war3mapImported/BTN<Name>.blp` and writes `CommandButtonsDisabled/DISBTN<Name>.blp` (sepia, no border). `-Preview` also writes a BTN | DISBTN side-by-side PNG to `%TEMP%`. BTN must be square and a power of two (64x64).

## Creating a relic

Use `ChainRing` as the reference.

1. Class in `Source/Game/Items/Relics/RelicTypes/` extending `Relic`. The constructor needs name, description, ability id (0 if passive), item id, cost and icon path. The shop reads name and description from here.
2. Add it in `ShopItem.ShopItemsRelic()` (`Source/UI/Frames/ShopItems/ShopItems.cs`). Without entries in `Upgrades`, the shop hides the upgrade button. Set `CountsTowardLimit = false` to not count towards `Relic.MaxRelics`.
3. Item in `items-objectdata.json` (base `rhth`, `iabi` = ability id). The inventory reads `unam`, `utip`, `utub`, `ides`, `uico` and `iico` from here, not from the class, so they must be set literally, with the same colour codes and text as the class description. Names are coloured like `|cffRRGGBBName|r`. Missing description or colours in the inventory means this JSON is out of sync with the class.
4. Active relics also need an ability in `abilities-objectdata.json`, its id in `RelicUtil.DisableRelicAbilities` and `EnableRelicAbilities`, and cooldowns via `RelicUtil.SetAbilityCooldown` on apply and `RelicUtil.SetRelicCooldowns` after use. New ids go in `Constants.cs`.
5. Icons: `BTNName.blp` in `war3mapImported` and a greyed `DISBTNName.blp` in `CommandButtonsDisabled` (generate it with `Scripts/New-DisBtn.ps1`). Fang of Shadows is the one relic without a `DISBTN` file; it uses a stock `ReplaceableTextures` icon.
6. Run `import-objects`, then `deploy`.
